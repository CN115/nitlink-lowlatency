NitLink CN115 audio-lab 1 — Windows x64 测试版
基于 nitlink-dev/nitlink 的 d522bdc。第三方实验 fork，不是上游官方版本。

运行
解压整个 zip 到新的可写目录，运行 NitLink.exe。保留所有子目录和 DLL。
需要 Windows 10 1809+ / Windows 11、DX11 GPU 和较新的 Microsoft Edge WebView2 Runtime。
VC++ 运行库随包携带；本包未进行代码签名。

F1 → Audio → Audio latency lab / 音訊低延遲實驗室
Capture FIFO target：采集缓冲目标，3–100 ms，默认 12 ms。
Render queue target：播放队列目标，3–100 ms，默认 10 ms。
Adaptive clock drift correction：默认开启；32 位浮点和 16 位 PCM 使用连续三次插值。
其他有效 PCM/浮点格式使用滤波后的单帧修正回退。关闭可作 A/B 对照。
设置立即保存，变更会短暂重启播放端，属预期行为。

调参建议
1. 默认 12 / 10 ms 播放 10 分钟，记录 FIFO、播放队列、引擎周期、ppm、欠载/丢弃/重新同步计数。
2. 每次降低 2–3 ms，播放相同素材。出现爆音或断音就提高缓冲。
3. USB 卡抖动较大可先试 20 / 15 ms，较保守可试 40 / 30 ms。
4. 测试播放设备切换、采集卡重连、休眠恢复；恢复后不应长时间播放旧音频。
5. 以相同设备、格式和素材对比上游；实际端到端延迟请用外部回录或音画同步素材测量。

诊断读数
FIFO + render 是应用管理的排队音频估算，并非端到端延迟。
不包含采集卡内部、USB 传输、Windows 混音处理、DAC/耳机（尤其蓝牙）延迟。
Windows/驱动可能把播放队列最低值提高到至少一个引擎周期加 1 ms。
ppm 表示当前修正量，不是独立测得的硬件时钟误差；正值更快消费输入。
欠载和丢弃计数按采样帧（不是声音片段）计，累计到进程退出。
设置页每秒刷新（视频循环运行时）；无画面时可按 Refresh。
DebugView 可接收每 5 秒一次的 [NitLink/Audio] stats。

实现
采集卡 → WASAPI capture（事件驱动，优先 IAudioClient3 短周期）→ FIFO →
自适应三次插值 → WASAPI render（事件驱动，短周期失败则兼容回退）→ Windows 混音/设备。
原版固定 FIFO 40 ms、render 30 ms；这只是两个配置目标，不能简单相加当作实测延迟。
漂移控制使用 1 秒低通 + 带抗积分饱和的 PI，按经过时间更新。
修正上限 ±2000 ppm，变化速率 400 ppm/秒。三次插值仅用于接近 1:1 的漂移，
不是带限的任意采样率转换器；设备间标称采样率/声道转换仍由 Windows 完成。
严重积压时丢弃旧数据重新同步；欠载后重新预填，避免不断插入细碎静音。

验证范围
包含合成时钟漂移、插值/环形缓冲、设置消息校验、配置持久化和上游自动化测试。
具体构建提交和运行结果见 BUILD.txt 与 GitHub Actions。
自动化和构建通过不代表真实采集卡测量；本版尚需你的 Windows 实机延迟和长时间试听验证。
反馈请包含：采集卡型号、驱动版本、Windows 版本、播放设备及格式、两项缓冲值、
漂移开关、实际引擎周期，以及 10–30 分钟后上述计数和主观听感。
