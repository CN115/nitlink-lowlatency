NitLink CN115 audio-lab 2 — Windows x64 测试版
基于 nitlink-dev/nitlink d522bdc，接续 audio-lab 1。第三方实验 fork。

本版针对“主板声卡播放队列卡在 11 ms”的改造
- 改为优先使用播放设备自己的混音格式协商 IAudioClient3 短周期。
- 程序内转换采集/播放端的 PCM 位深、浮点格式、采样率和常见声道布局。
- 使用带限的多相 sinc 重采样，同时处理标称采样率差异和慢速时钟漂移。
- 显示原生格式最小周期、默认周期、实际使用周期及短周期失败的阶段/HRESULT。
- 显示用户目标、有效目标、处理后的实际队列占用，以及 FIFO 一秒均值和范围。

运行和测试
解压整个 zip 到新的可写目录，运行 NitLink.exe。保留所有 DLL 和子目录。
需要 Windows 10 1809+ / Windows 11、DX11 GPU 和当前 Microsoft Edge WebView2 Runtime。
VC++ 运行库随包携带。本包未代码签名。

F1 → Audio → Audio latency lab / 音訊低延遲實驗室
先保留 Capture FIFO 12 ms，把 Render queue 改为 3 ms，保持 Drift 开启。
请优先反馈底部完整的诊断文字，尤其是：
  Native shared low-period / Compatibility shared
  native min / default / actual
  fallback 阶段和 HRESULT（如果有）

若 Native shared low-period 的 actual 低于 10 ms，说明这条路径已成功降低引擎周期。
若 native min 本身为 10 ms，本版共享路径不能强行越过驱动公布的下限。
若 min 低于 10 ms 却回退，请保留错误码，继续定位设备占用、格式或驱动限制。
本版没有启用独占模式，也不会独占声卡或修改 Windows 全局声音设置。
如果出现爆音或欠载持续增加，把播放目标调高到 5 / 8 / 10 ms；FIFO 可提高至 20 ms。

设置范围和读数
Capture FIFO / Render queue 都为 3–100 ms；保存后立即生效，播放端短暂重启。
继承 lab1 配置时保留原有数值；新配置默认仍是 12 / 10 ms。
播放有效目标至少为实际引擎周期 + 1 ms（并受已分配端点缓冲大小约束）。
因此引擎实际为 10 ms 时，低于 11 ms 的设置仍被保护下限抬高。
只有先降低实际引擎周期，才能安全降低这条路径的播放队列。

FIFO 和 render 是同一次音频泵处理后的快照；render 从 WASAPI 再查询取得。
FIFO 按采集采样率换算，render 按播放采样率换算，排除 FIFO 中已播放的滤波历史。
FIFO 的一秒均值按时间加权，范围来自该时间窗内处理后的样本；启动不足一秒时为零。
这些都是队列占用，并非端到端实测延迟。FIFO 包级锯齿波动是预期行为。
驱动、USB、采集卡、Windows 音效处理、DAC/耳机等额外延迟不包含在内。
ppm 是控制器修正量，不是独立测得的硬件时钟偏差。
欠载按播放采样帧计，丢弃按采集采样帧计；采样率不同时二者不能直接比较。

音频管线
采集卡 → WASAPI 事件采集 → 采集格式 FIFO → sinc 重采样/声道与位深转换 →
播放设备原生格式的 WASAPI 短周期共享流 → Windows 混音/驱动 → 声卡。
如果原生短周期初始化失败，则回退到让 Windows 执行格式转换的兼容共享流。
立体声到多声道仅映射前左/前右，其他通道静音；单声道复制至前左/前右；
立体声到单声道取平均。未实现的布局变换交给兼容路径，避免错误声道解释。
程序转换支持 PCM8/16/24/32（含有效位数）、float32/64，采样率比 1/8 至 8。
其余合法格式保留兼容路径和滤波后的单帧漂移修正。
关闭 Drift 只关闭时钟偏差补偿，必要的标称采样率/格式转换仍继续。

sinc 滤波器采用 Blackman 窗、512 个相位并在相位间插值；64–512 taps，
初始化时预计算系数，音频泵不分配内存。滤波有短暂前视与高频过渡带，不宣称位元完美。
漂移控制沿用时间驱动的低通 + PI，限幅 ±2000 ppm，修正变化率 400 ppm/秒。

验证范围
自动化覆盖 PCM 编解码、24-in-32 对齐、声道映射、周期对齐、滤波响应、
跨采样率环形 FIFO、分块相位连续性、同一快照的单位换算，以及原有漂移/设置回归。
Windows 构建与自动化通过不代表真实主板声卡已验证。需要在你的机器上确认
实际周期、试听质量、长时间稳定性，以及切换设备/重连/休眠后的恢复情况。
